Executive Read

What is now strong

  • Work-order detail has become the core command center: services, parts, time, QC, SOP, messages, accounting links, customer/cart drawers, profile edits, and quote conversion.
  • Inventory and purchasing are mostly actionable: PO drill-in, lifecycle actions, receiving, reservations, replenishment, default-vendor assignment from planning, variance, payable review, import/export, stock movement history, manual stock adjustment posting, stock transfer posting, cycle-count batch posting, and bulk row actions.
  • Planning masters now let operators create, lock, and release build configurations, author BOM revisions from live active parts, approve BOMs, capture approval notes and change history, compare live configuration/BOM/route versions, prefill new revisions from existing masters, review full ECO history, and reuse released configuration/BOM pairs as build packages.
  • Dashboards, KPI cards, reporting cards, and many workspace links now deep-link to real filtered destinations.
  • Training, reporting, and admin catalogs have moved from placeholder status to useful operational destinations.
  • CI, QA smoke, QA coverage, CD, and Pages are green on the latest merged production baseline.
  • Reporting now has a live in-app automation path: saved-view subscriptions, pause/enable controls, run-now export evidence, and downloadable CSV output.
  • Accounting now has a live operational ledger, posted journal-entry model, guarded journal-posting action, trial-balance/period-close readiness, period locks, reversals, and a deployed close-package report assembled from live documents.

What still keeps this from full production confidence

  • ShopMonkey cutover is no longer blocked on zero inventory parts or zero purchase orders: read-only source enrichment produced 189 valid parts and 11 valid purchase orders, the preflight moved to WARN, and the isolated loader rehearsal passed. The connector now uses a dense ShopMonkey inventory-part sweep instead of stopping at the first 100 search rows. The preflight now groups warning review into one unknown-customer row and 68 work orders missing customer IDs. Remaining cutover confidence depends on sign-off or repair for those buckets, the 48-part reported-total coverage gap, and shared staging UAT.
  • Planning now has routing/job-card, build-configuration, and BOM masters with effective windows, costing metadata, QC/evidence seeding, and approval history. Work-order execution now links back to the source configuration, BOM, route template, and ECO history, released packages now expose a live ECO review pack, and deployed package-level sign-off evidence is required before packages are accepted for production use.
  • Accounting is still integration-first, but ready operational ledger entries now promote into first-party immutable journals and those journals feed deployed close readiness, reversals, period locks, close-package export, and persisted invoice/payment document snapshots instead of reconstructing period evidence only from sync rows.
  • API smoke route exceptions are back to zero after live smoke proved GET /accounting/reports/close-package reaches the protected authorizer path.

These percentages are planning estimates. They are based on merged code, recent QA results, route coverage, architecture docs, and the current actionability tracker.
